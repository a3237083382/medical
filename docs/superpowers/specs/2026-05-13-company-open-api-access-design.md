# 保险公司开放接口接入设计

## 背景

平台定位是 B2B API 服务。保险公司承保前查询医疗数据时，不应在平台门户页面手工输入姓名和身份证号查询；保险公司应按照平台提供的接口文档，在自己的业务系统中调用开放接口。

公司门户用于账号自助、接口接入说明、查询记录、费用流水和充值流程，不承载实际医疗查询操作。

## 已确认需求

- 当前阶段选择“接口文档页 + 开放接口框架”。
- 暂不接真实医院/卫健委数据源，开放接口先返回标准示例脱敏数据。
- 开放接口真实执行鉴权、查价、查询日志写入，为后续真实数据源接入打好闭环。
- 开放接口采用统一入口：`POST /open/api/medical/query`。
- 鉴权采用 `AppKey + AppSecret` 签名机制。
- 公司门户只展示 `AppKey`，不长期展示 `AppSecret`。
- `/company/query` 路径保留，但页面名称和内容改为“接口接入”。

## 保险公司密钥交付

管理员在后台新增保险公司时，系统为该公司自动生成唯一的 `AppKey` 和 `AppSecret`。

- `AppKey`：每家公司唯一，可在公司门户“接口接入”页展示。
- `AppSecret`：每家公司唯一，作为签名密钥，不在公司门户长期明文展示。
- `AppSecret` 由管理员通过安全渠道交付给保险公司，例如合同附件、加密邮件或企业内部安全渠道。
- 如果 `AppSecret` 泄露或遗失，后续由管理员重置密钥，旧密钥失效。

## 公司门户页面

`/company/query` 改为“接口接入”页面。

页面展示：

- 当前公司的 `AppKey`
- 开放接口地址
- 签名请求头说明
- 签名算法说明
- 请求示例
- 返回示例
- 当前可用接口列表，数据来自 `biz_query_price`
- 每个接口的 `queryType`、接口名称和单次费用
- 错误码说明
- 跳转“查询记录”和“费用流水”的入口

页面删除：

- 姓名输入框
- 身份证号输入框
- 页面查询按钮
- 页面查询结果区域

## 开放接口

接口地址：

```text
POST /open/api/medical/query
```

请求头：

```text
X-App-Key: 保险公司 AppKey
X-Timestamp: 当前毫秒时间戳
X-Nonce: 每次请求唯一随机字符串
X-Sign: 签名值
```

请求体示例：

```json
{
  "queryType": "hospital_visit",
  "name": "张三",
  "idCard": "430102199001011234"
}
```

签名规则：

```text
sign = SHA256(appKey + timestamp + nonce + body + appSecret)
```

服务端处理流程：

1. 根据 `X-App-Key` 查询保险公司。
2. 校验公司存在且状态正常。
3. 使用数据库中的 `AppSecret` 重新计算签名。
4. 校验 `X-Timestamp` 未过期，`X-Nonce` 格式合法。
5. 根据 `queryType` 查询 `biz_query_price`。
6. 记录 `biz_query_log`，包含公司、查询类型、脱敏查询参数、费用、请求 IP、请求时间和状态。
7. 返回标准示例脱敏医疗数据。

## 查询价目关系

开放接口的查询能力由后台“查询价目”配置驱动：

```text
biz_query_price.query_type -> 接口能力标识
biz_query_price.query_name -> 接口能力名称
biz_query_price.fee -> 单次查询费用
biz_query_price.status -> 是否启用
```

如果 `queryType` 不存在或已停用，开放接口返回错误并写入失败查询日志。

## 返回数据

当前阶段返回标准示例脱敏数据，用于保险公司联调接口格式、签名和日志计费链路。

返回示例：

```json
{
  "code": 200,
  "msg": "查询成功",
  "data": {
    "queryType": "hospital_visit",
    "queryName": "门诊住院记录查询",
    "fee": 10.00,
    "name": "张*",
    "idCard": "4301**********1234",
    "summary": "未发现影响承保的高风险医疗记录",
    "records": []
  }
}
```

真实医院/卫健委数据源接入后，只替换数据查询实现，保留鉴权、查价、日志和计费框架。

## 错误处理

接口统一返回 JSON。

常见错误码：

- `401`：缺少签名请求头、AppKey 不存在、签名错误或时间戳过期
- `403`：保险公司账号已停用
- `400`：请求参数缺失或 `queryType` 不存在
- `500`：系统异常

失败请求在能识别保险公司的情况下写入查询日志，费用为 `0.00`，状态为失败。

## 测试标准

实现完成后至少验证：

- `/company/query` 不再出现手工查询表单。
- `/company/query` 展示接口接入文档、AppKey 和查询价目列表。
- 公司门户不展示 `AppSecret`。
- 无签名调用 `/open/api/medical/query` 返回失败。
- 错误签名调用返回失败。
- 正确签名调用返回成功示例数据。
- 成功调用写入 `biz_query_log`，状态为成功，费用等于对应 `queryType` 价目。
- 不存在或停用的 `queryType` 返回失败，并写入失败日志。
- 前端生产构建通过。
- 后端编译通过。
