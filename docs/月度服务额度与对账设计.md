# 月度服务额度与对账设计

## 目标

将保险公司端从“余额/充值/单次扣费”的直观收费表达，调整为“月度服务额度 + 月度对账”。保险公司端只突出服务启用、使用进度和对账核对；内部管理后台继续保留预算、价格、账单和资金流水管理能力。

## 业务规则

1. 按自然月控制服务额度，每家保险公司维护一个月度预算。
2. 每个接口支持公司级价格，同一接口对不同保险公司可以配置不同标准。
3. 公司级价格分为查得数据标准和未查得标准。
4. 查询前按该公司该接口的较高标准预留预算，预留后超过本月预算则拒绝查询。
5. 查询完成后按实际结果确认金额：查得数据按 `hit_fee`，未查得按 `no_result_fee`。
6. 鉴权失败、参数错误、系统异常不进入月账单；查询中异常会释放已预留额度。
7. 月账单按公司和月份生成，明细按接口类型和结果类型汇总。

## 数据模型

- `biz_insurance_company.monthly_budget`：公司月度预算。
- `biz_insurance_company.budget_enabled`：预算控制是否启用。
- `biz_company_query_price`：公司级接口价格，包含 `hit_fee` 和 `no_result_fee`。
- `biz_monthly_usage`：月度额度使用表，保存已确认金额和预留金额。
- `biz_query_log` 新增 `billing_month`、`result_status`、`fee_snapshot`、`price_config_id`。
- `biz_monthly_bill`、`biz_monthly_bill_detail`：月度账单和账单汇总明细。

## 前后端表现

- 管理后台“保险公司管理”维护月度预算和预算控制状态。
- 管理后台“查询价目”维护公司级接口标准。
- 管理后台“月度账单”生成并查看月度账单。
- 保险公司端首页显示服务状态、使用进度、预计剩余可用次数和月度对账入口。
- 保险公司端查询页不展示接口价格和本次金额，只展示查询编号、结果类型和脱敏数据。
- 保险公司端“充值”相关文案调整为“额度申请”和“额度申请记录”。

## 验证要点

- 不同公司同一接口按各自公司级价格入账。
- 同一公司同一接口查得/未查得按不同标准入账。
- 月预算不足时查询前拦截，不调用数据源、不写成功日志。
- 严格按较高标准预留，避免本月预算被超用。
- 月账单按自然月、接口类型、结果类型汇总。
