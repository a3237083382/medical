# 实时与精准延时查询需求文档

> 日期：2026-08-13  
> 阶段：需求确认文档  
> 范围：只描述需求和业务规则，不包含代码实现  
> 配套计划：`docs/实时与精准延时查询需求变更工作计划.md`

---

## 1. 背景

保险公司在承保、核保或理赔前，需要查询投保人的医疗、参保、保险相关信息。平台现在需要从原来的单一查询模式，调整为两种服务：

1. **实时数据查询**
   - 平台直接调用数产集团接口。
   - 数产集团返回什么数据，平台就给保险公司返回什么数据。
   - 平台不对实时返回数据做脱敏、摘要、字段转换或业务加工。
   - 该服务费用较低，数据详细程度取决于数产集团接口。

2. **精准延时数据查询**
   - 保险公司提交姓名和身份证号。
   - 系统生成一条待处理请求。
   - 平台管理/运营人员看到请求后，人工查询公司自有数据。
   - 平台管理/运营人员可上传 Excel，也可逐行录入结果。
   - 结果保存并上传完毕后，保险公司可在页面提示和历史记录中查看。
   - 该服务不要求保险公司停留在页面等待。

---

## 2. 用户角色

| 角色 | 说明 | 主要操作 |
| ---- | ---- | -------- |
| 保险公司用户 | 使用查询服务的外部客户 | 发起实时查询、发起精准延时查询、查看查询结果和历史记录 |
| 平台管理/运营人员 | 平台内部统一后台用户 | 查看精准延时请求、人工查询数据、上传或录入结果、修改结果、查看公司日志、查看实时和精准延时查询记录、维护权限和价格 |

---

## 3. 服务模式

### 3.1 实时数据查询

实时数据查询用于低成本、快速获取数据。

业务规则：

- 保险公司输入姓名和身份证号。
- 保险公司选择实时查询。
- 后台调用数产集团接口。
- 数产集团返回什么，系统就返回什么。
- 系统只负责中转、鉴权、日志、计费，不负责加工数据。
- 查询完成后立即在保险公司页面展示结果。
- 查询记录进入保险公司历史查询记录。

返回规则：

- 查得数据：展示数产集团返回的数据。
- 未查得：展示数产集团返回的未查得信息。
- 查询异常：展示查询失败提示，并记录失败日志。

### 3.2 精准延时数据查询

精准延时数据查询用于更详细的数据查询，不要求实时返回。

业务规则：

- 保险公司只需要输入姓名和身份证号。
- 精准延时数据不区分查询类型。
- 平台管理/运营人员后台查到什么数据，就整理后返回什么数据。
- 保险公司提交后，系统立即生成请求记录。
- 保险公司可以退出页面，不需要等待人工处理。
- 平台管理/运营人员处理完成后，保险公司页面出现提示。
- 保险公司可以点击提示查看结果。
- 保险公司也可以在历史查询记录中查看以前的实时和精准延时查询。

## 4. 保险公司端需求

### 4.1 查询页面

查询页面需要支持两种模式切换：

- 实时查询
- 精准延时数据

实时查询表单：

- 姓名
- 身份证号
- 实时查询接口或查询项目
- 查询按钮

精准延时数据表单：

- 姓名
- 身份证号
- 提交查询按钮

精准延时提交后页面显示：

- 请求已提交
- 请求编号
- 姓名
- 身份证号
- 提交时间
- 查询状态：未查询/已查询
- 结果上传：未上传/已上传
- 当前提示：等待平台处理，处理完成后可在本页面或历史记录查看

### 4.2 已处理提示

保险公司登录或进入查询页面时，如果有已处理但未查看的精准延时结果，页面需要有明显提示。

提示内容建议：

- 有新的精准延时查询结果
- 显示姓名、身份证号脱敏展示、提交时间、处理完成时间
- 点击后进入结果详情

说明：

- 不要求保险公司每次重新查询才能看到结果。
- 已处理结果应当可以通过提示直接进入。
- 已处理结果也应当可以在历史查询记录中找到。

### 4.3 历史查询记录

保险公司需要能查看自己的所有查询历史。

历史记录包括：

- 实时查询记录
- 精准延时查询记录

实时查询记录字段：

- 查询方式：实时查询
- 姓名
- 身份证号
- 查询接口
- 查询时间
- 查询结果：查得/未查得/失败
- 费用
- 操作：查看详情

精准延时查询记录字段：

- 查询方式：精准延时数据
- 姓名
- 身份证号
- 提交时间
- 查询状态：未查询/已查询
- 结果上传：未上传/已上传
- 处理完成时间
- 费用
- 操作：查看状态/查看结果

历史记录规则：

- 保险公司只能看到本公司的记录。
- 实时和精准延时记录可以在同一页面展示，也可以用页签区分。
- 未上传的精准延时记录显示“处理中”。
- 已上传的精准延时记录显示“查看结果”。

## 5. 精准延时查询提交规则

### 5.1 基本字段

保险公司提交精准延时查询时，需要生成请求记录。

请求记录字段：

| 字段 | 说明 |
| ---- | ---- |
| 姓名 | 保险公司输入 |
| 身份证号 | 保险公司输入 |
| 公司名称 | 根据登录公司自动带出 |
| 查询状态 | 未查询/已查询 |
| 结果上传 | 未上传/已上传 |
| 提交时间 | 系统自动记录 |
| 处理时间 | 平台管理/运营人员处理完成时记录 |
| 结果说明 | 平台管理/运营人员填写，返回给保险公司 |

### 5.2 重复提交处理

同一个保险公司重复提交同一个人时，系统需要做处理，避免一直生成重复请求。

推荐规则：

1. 如果同一公司、同一姓名、同一身份证号已经有“未查询”或“未上传”的请求，则不新建请求。
2. 页面提示：该人员已有待处理的精准延时查询，请等待处理完成。
3. 系统返回已有请求编号和当前状态。
4. 如果已有请求已上传完毕，再次提交时可以新建请求，也可以提示查看历史结果。

建议默认采用：

- 未完成请求：复用已有请求，不重复创建。
- 已完成请求：允许再次提交，但页面同时提示已有历史结果可查看。

## 6. 平台后台需求

### 6.1 精准延时查询列表

后台需要新增精准延时查询管理页面。

列表字段：

- 公司名称
- 姓名
- 身份证号
- 查询状态：未查询/已查询
- 结果上传：未上传/已上传
- 提交时间
- 处理人
- 处理时间
- 操作

筛选条件：

- 公司名称
- 姓名
- 身份证号
- 查询状态
- 结果上传
- 提交时间范围

操作按钮：

- 详情
- 上传/处理
- 查看结果

显示规则：

- 未上传请求显示“上传/处理”按钮。
- 已上传请求显示“查看结果”和“修改结果”。
- 已查询但未上传时，仍不能让保险公司看到最终结果。

### 6.2 结果上传/处理页面

点击未上传请求后，进入结果上传/处理页面。

页面需要包含：

- 请求信息区域：公司名称、姓名、身份证号、提交时间、当前状态
- Excel 上传区域：选择文件、导入 Excel 文件内容
- 手工录入区域：逐行新增数据
- 结果明细表格：展示导入或手工录入的数据
- 结果说明：填写返回给保险公司的提示信息
- 操作按钮：确定保存、上传完毕、返回

### 6.3 Excel 导入规则

当前没有固定标准模板，因此不能把字段写死。

需求规则：

- 支持上传 Excel。
- 系统读取 Excel 的表头和数据行。
- Excel 有什么字段，页面就尽量展示什么字段。
- 导入后的数据要能编辑。
- 导入后的数据要能删除。
- 平台管理/运营人员可以继续手工新增行。
- 未识别或不固定的字段，也需要保存下来，避免数据丢失。

### 6.4 手工录入规则

当没有 Excel 文件，或者 Excel 数据不完整时，平台管理/运营人员可以手工添加数据。

需求规则：

- 支持新增一行。
- 支持编辑一行。
- 支持删除一行。
- 支持保存草稿。
- 支持上传完毕。

### 6.5 保存和上传完毕

按钮含义：

- **确定保存**：保存当前草稿，保险公司暂时看不到最终结果。
- **上传完毕**：确认该请求处理完成，保险公司可以查看结果。

状态变化：

| 操作 | 查询状态 | 结果上传 | 保险公司是否可见 |
| ---- | -------- | -------- | ---------------- |
| 新提交 | 未查询 | 未上传 | 只看到处理中 |
| 保存草稿 | 未查询或已查询 | 未上传 | 只看到处理中 |
| 上传完毕 | 已查询 | 已上传 | 可以查看结果 |
| 修改已上传结果 | 已查询 | 已上传 | 查看最新结果 |

## 7. 结果返回规则

### 7.1 有详细数据

如果平台管理/运营人员查到了详细数据：

- 上传或录入结果明细。
- 点击上传完毕。
- 保险公司可查看明细。
- 此类结果算查得。
- 查询流程完毕后扣费。

### 7.2 有信息提示但无明细数据

例如：查询到这个人买过保险、参过保、或有类似线索，但当前没有可返回明细。

返回规则：

- 不返回明细数据。
- 在保险公司查询信息区域显示提示。
- 提示由平台管理/运营人员填写。
- 示例：已查询到相关参保信息，但当前无可返回明细。

计费规则：

- 该场景需要在后台标记为一种独立结果状态，建议叫“有提示无明细”。
- 是否扣费后续可按业务价格规则确定。

### 7.3 数据库也没有患者信息

如果平台管理/运营人员在公司自有数据库中也没有查到这个患者：

- 结果状态为未查得。
- 不返回明细数据。
- 可以显示“未查询到该人员相关信息”。
- 不扣费。

---

## 8. 修改规则

精准延时结果上传完毕后，先设计为允许修改。

需求规则：

- 平台管理/运营人员可以修改已上传结果。
- 修改后保险公司看到最新结果。
- 系统需要记录修改人、修改时间和修改说明。
- 如果后续需要审计更严格，可以再增加历史版本记录。

---

## 9. 计费规则

### 9.1 实时查询计费

- 实时查询完成后按实时查询价格计费。
- 查得和未查得是否不同价格，沿用现有价格配置规则。
- 查询失败不应按成功查询扣费，具体按现有规则处理。

### 9.2 精准延时查询计费

确认规则：

- 精准延时查询只有整个查询流程完毕后才扣钱。
- “上传完毕”代表流程完毕。
- 如果内部数据库也没有该患者信息，算未查得，不扣钱。

推荐计费状态：

| 结果 | 是否返回数据 | 是否扣费 | 说明 |
| ---- | ------------ | -------- | ---- |
| 查得 | 返回明细或有效结果 | 扣费 | 内部查到可返回内容 |
| 有提示无明细 | 不返回明细，只返回提示 | 待确认 | 例如买过保险但当前无明细 |
| 未查得 | 无明细，无有效信息 | 不扣费 | 数据库没有该患者信息 |

## 10. 日志需求

### 10.1 保险公司历史查询

保险公司需要能看到自己曾经查过哪些人。

记录范围：

- 实时查询
- 精准延时查询

保险公司可以从历史记录中看到：

- 查询方式
- 查询人姓名
- 身份证号
- 查询或提交时间
- 当前状态
- 是否已上传结果
- 是否扣费
- 查看详情入口

### 10.2 后台按公司查看日志

后台日志需要支持按公司查看。

需求：

- 平台管理/运营人员点击某个公司。
- 进入该公司的查询日志详情。
- 能看到实时数据查询日志。
- 能看到精准延时数据查询日志。

建议页面结构：

- 公司基础信息
- 实时查询日志页签
- 精准延时查询日志页签

实时日志展示：

- 查询类型
- 姓名
- 身份证号
- 查询时间
- 查询结果
- 费用

精准延时日志展示：

- 姓名
- 身份证号
- 提交时间
- 查询状态
- 结果上传
- 处理人
- 处理时间
- 费用

## 11. 页面提示文案

精准延时提交成功：

> 已提交精准延时查询，请等待平台处理。处理完成后可在当前页面提示或历史查询记录中查看结果。

重复提交未完成请求：

> 该人员已有待处理的精准延时查询，请勿重复提交。你可以在历史查询记录中查看处理进度。

有新结果：

> 你有新的精准延时查询结果，点击查看。

未上传：

> 平台正在处理该查询，请稍后查看。

未查得且不扣费：

> 未查询到该人员相关信息，本次不扣费。

有提示无明细：

> 已查询到相关信息，但当前无可返回明细，请以页面提示为准。

## 12. 验收标准

### 12.1 实时查询

- [ ] 保险公司可以发起实时查询。
- [ ] 实时查询返回数产集团原始数据。
- [ ] 实时查询结果进入历史查询记录。
- [ ] 实时查询日志可在后台按公司查看。

### 12.2 精准延时提交

- [ ] 保险公司只输入姓名、身份证即可提交精准延时查询。
- [ ] 提交后立即生成请求记录。
- [ ] 页面不等待人工结果。
- [ ] 重复提交未完成请求时，不重复创建新请求。

### 12.3 内部处理

- [ ] 后台能看到所有精准延时请求。
- [ ] 请求列表包含姓名、身份证、公司名称、查询状态、结果上传状态。
- [ ] 未上传请求有上传/处理按钮。
- [ ] 支持 Excel 上传。
- [ ] 支持逐行添加数据。
- [ ] 支持编辑和删除明细。
- [ ] 支持保存草稿。
- [ ] 支持上传完毕。
- [ ] 上传完毕后状态变为已查询、已上传。

### 12.4 保险公司查看结果

- [ ] 已处理的精准延时结果会在保险公司页面提示。
- [ ] 点击提示可以查看结果。
- [ ] 历史查询记录可以查看以前查过的实时和精准延时记录。
- [ ] 未上传记录显示处理中。
- [ ] 数据库无患者信息时显示未查得，并且不扣费。

### 12.5 日志和费用

- [ ] 后台可以按公司查看实时查询日志。
- [ ] 后台可以按公司查看精准延时查询日志。
- [ ] 精准延时查询在流程完毕后才扣费。
- [ ] 数据库无患者信息时不扣费。

---

## 13. 暂不确定但需保留扩展的事项

1. 精准延时上传 Excel 的标准模板暂未确定。
2. 精准延时结果字段暂不固定，需要支持动态字段。
3. “有提示无明细”是否扣费，需要后续业务确认。
4. 已上传结果修改是否需要保留历史版本，先按可修改、记录操作日志设计。
