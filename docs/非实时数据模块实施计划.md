## 本次新增：实时查询缓存到历史库

### 目标
保险公司调用实时查询接口（medical_insurance等）时，自动将原始数据缓存到历史数据库，供后续历史数据查询使用。

### 业务规则
1. 每次实时查询拿到原始数据后，检查该患者在历史库是否已有相同内容的记录
2. 通过对比 biz_his_bigdata 中最新的 dataJson 与本次原始数据JSON是否一致来判断
3. 一致 → 跳过（数据未更新）
4. 不一致 → 追加新记录到 biz_his_clinic_visit + biz_his_bigdata

### 实施步骤

**Step 1：IBizHistoryQueryService 新增 cacheQueryResult() 方法**
- 新增方法：cacheQueryResult(queryType, rawData)
- 提取 patientName + idCard
- 查询该患者最新的 bigdata 记录 dataJson
- 对比 JSON，一致则跳过
- 不一致则构造 BizHisClinicVisit + BizHisBigdata 并插入

**Step 2：BizHistoryQueryServiceImpl 实现缓存逻辑**
- 实现 cacheQueryResult() 方法
- 查重逻辑：SELECT data_json FROM biz_his_bigdata WHERE patient_name=? AND id_card=? ORDER BY id DESC LIMIT 1
- 提取结构化字段存入 clinic_visit 表
- 完整JSON存入 bigdata 表

**Step 3：MedicalQueryServiceImpl.query() 增加缓存调用**
- 在实时查询分支中，拿到原始数据后、脱敏前，调用 historyQueryService.cacheQueryResult()
- 仅在数据源返回非空数据时调用

**Step 4：编译 + 部署 + 验证**
- mvn clean package -DskipTests
- 启动后端
- 测试：调实时接口 → 查历史库是否有缓存 → 再次调实时接口验证不重复缓存

### 验证标准

1. 第一次实时查询患者X → 历史库中出现该患者记录 ✅
2. 第二次实时查询患者X（数据未变） → 历史库中不新增记录 ✅
3. 调历史查询接口查患者X → 返回HIT + 详细数据 ✅
4. 查不存在的患者 → 返回NO_RESULT ✅
