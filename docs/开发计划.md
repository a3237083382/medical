## 技术栈

| 层面     | 选型                                          |
| -------- | --------------------------------------------- |
| 后端框架 | RuoYi-Vue (master, Spring Boot 4.x + JDK 17+) |
| 前端     | Vue3 + Element Plus + Vite                    |
| 接口层   | Magic-API 2.3.0 (org.ssssssss)                |
| 数据库   | MySQL 8.0 (utf8mb4)                           |
| 认证机制 | AppKey + HMAC-SHA256 签名                     |
| 缓存     | Redis                                         |

## Phase 5：AppKey/Sign 签名认证系统（1.5-2 天）

**目标**：对外 API 路径经过签名认证，合法请求放行，非法请求拦截。

### 签名协议

```
请求头: X-App-Key, X-Timestamp, X-Nonce, X-Sign
签名算法: HMAC-SHA256(timestamp + "\n" + nonce + "\n" + body, appSecret)
时效窗口: ±5 分钟
Nonce 去重: Redis SET + EXPIRE (TTL = 6 分钟)
```

- [ ] 5.1 实现 `SignUtil.java`（HMAC-SHA256 签名生成和验证）
- [ ] 5.2 实现 `SignAuthInterceptor.java`（AppKey 查公司 → 校验状态 → 验证签名 → Nonce 去重）
- [ ] 5.3 在 `WebMvcConfig.java` 注册拦截器到 `/api/v1/**`
- [ ] 5.4 在 `SecurityConfig.java` 放行 `/api/v1/**`
- [ ] 5.5 实现请求体缓存 Filter（`ContentCachingRequestWrapper`）
- [ ] 5.6 创建受保护测试接口，用 curl 验证签名流程
- [ ] 5.7 编写客户端签名示例脚本（Python 或 Shell）

**验证标准**：无签名头 → 401，签名错误 → 401，Nonce 重用 → 401，超时 → 401，正确签名 → 200。

## 关键技术难点

| 难点                          | 方案                                                                                       |
| ----------------------------- | ------------------------------------------------------------------------------------------ |
| AppKey/Sign 与 JWT Token 共存 | `/api/v1/**` 在 SecurityConfig 中 `permitAll()`，由 `SignAuthInterceptor` 做签名认证 |
| Magic-API 调用 Java 扣费逻辑  | `@MagicModule` + `@MagicFunction` 暴露 Spring Bean                                     |
| 请求体多次读取                | `OncePerRequestFilter` + `ContentCachingRequestWrapper`                                |
| 并发扣款                      | 原子 SQL `UPDATE balance = balance - ? WHERE balance >= ?`                               |
| 日志不可篡改                  | 数据库触发器禁止 UPDATE/DELETE + 应用层不提供修改接口                                      |
| 多数据源对接与路由            | 定义 `MedicalDataSource` 接口，策略模式动态路由，根据查询类型选择数据源                     |
| 数据源不可用降级              | 健康检查 + 熔断机制（`@CircuitBreaker`），不可用时切备用数据源或返回明确错误码              |
| 批量保险公司对接              | 自助开户页面 + 标准对接文档 + 签名示例脚本，减少一对一的沟通成本                           |
