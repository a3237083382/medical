# 保险公司嵌入式查询接口清单

> 日期：2026-08-14  
> 状态：接口契约草案，编码前基线  
> 保险公司接口前缀：`/company/embed/medical`

## 1. 通用约定

所有接口通过请求头传递 AppKey：

```http
X-App-Key: <company-app-key>
```

JSON 成功响应：

```json
{
  "code": 200,
  "msg": "success",
  "data": {}
}
```

JSON 失败响应：

```json
{
  "code": 400,
  "msg": "姓名和身份证号不能为空",
  "errorCode": "INVALID_PARAM"
}
```

列表接口统一支持 `pageNum`、`pageSize`。时间使用 `yyyy-MM-dd HH:mm:ss`，金额使用十进制定点数，批次编号和请求编号以字符串返回。

## 2. 已有接口处理策略

| 现有接口 | 处理策略 |
| --- | --- |
| `GET /query-types` | 保留，返回当前公司可用的实时查询项目和价格 |
| `POST /query` | 保留并规范为单人实时查询，不承担精准延时提交 |
| `GET /usage` | 保留，返回月度额度和服务状态 |
| `/open/api/medical/query` | 不供新嵌入页面使用，后续单独评估兼容性 |

## 3. 接入与基础信息

### 3.1 验证 AppKey

```http
GET /company/embed/medical/access
```

返回当前公司脱敏信息、服务状态和能力开关。页面以此接口结果作为“已接入”的唯一依据。

### 3.2 查询项目

```http
GET /company/embed/medical/query-types
```

仅返回启用且当前公司有权使用的实时查询项目：

```json
{
  "queryType": "medical_all",
  "queryName": "医疗大数据",
  "hitFee": 50.00,
  "noResultFee": 0.00
}
```

### 3.3 月度用量

```http
GET /company/embed/medical/usage
```

沿用现有预算、已使用、已预留、剩余额度和服务状态字段。

## 4. 单人查询

### 4.1 单人实时查询

```http
POST /company/embed/medical/query
Content-Type: application/json
```

```json
{
  "queryType": "medical_all",
  "queryParams": {
    "name": "张三",
    "idCard": "430102199001011234"
  }
}
```

返回 `requestNo`、`processStatus`、`resultStatus`、费用和动态 `data`。

### 4.2 单人精准延时提交

```http
POST /company/embed/medical/delayed/requests
Content-Type: application/json
```

```json
{
  "name": "张三",
  "idCard": "430102199001011234"
}
```

返回请求编号、状态和 `reused`。重复未完成请求返回 `200` 及原请求，不以错误处理。

## 5. 批量导入与提交

### 5.1 下载名单模板

```http
GET /company/embed/medical/batches/template
```

返回 `.xlsx` 文件，列为姓名和身份证号。

### 5.2 解析名单预览

```http
POST /company/embed/medical/batches/import-preview
Content-Type: multipart/form-data
```

表单字段：`file`。只接受 `.xlsx`、`.xls`，最多 500 行有效人员数据。

返回：

```json
{
  "totalCount": 3,
  "validCount": 2,
  "invalidCount": 1,
  "duplicateCount": 0,
  "rows": [
    {
      "rowNo": 2,
      "originalName": "张三",
      "originalIdCard": "430102199001011234",
      "name": "张三",
      "idCard": "430102199001011234",
      "valid": true,
      "errors": []
    }
  ]
}
```

### 5.3 重新校验预览数据

```http
POST /company/embed/medical/batches/validate
Content-Type: application/json
```

请求体包含页面修改后的 `rows`，返回与导入预览相同的统计和校验结果，不创建正式记录。

### 5.4 创建批次

```http
POST /company/embed/medical/batches
Content-Type: application/json
```

```json
{
  "serviceMode": "REALTIME",
  "queryType": "medical_all",
  "rows": [
    { "rowNo": 2, "name": "张三", "idCard": "430102199001011234" }
  ]
}
```

`serviceMode` 为 `REALTIME` 或 `DELAYED`。`REALTIME` 必须提供 `queryType`，`DELAYED` 忽略该字段。服务端重新执行全部校验后，以单一事务创建批次和明细。

## 6. 批次与明细

### 6.1 批次历史

```http
GET /company/embed/medical/batches
```

筛选参数：`serviceMode`、`batchStatus`、`beginTime`、`endTime`、分页参数。

### 6.2 批次详情

```http
GET /company/embed/medical/batches/{batchNo}
```

返回批次统计、费用汇总和是否允许整批取消/导出。

### 6.3 批次人员明细

```http
GET /company/embed/medical/batches/{batchNo}/items
```

筛选参数：`processStatus`、`resultStatus`、`keyword`、分页参数。

### 6.4 取消整个批次

```http
POST /company/embed/medical/batches/{batchNo}/cancel
```

仅将符合 `PENDING + NOT_UPLOADED` 的明细改为 `CANCELLED`。返回取消数量、不可取消数量和最新批次状态。

### 6.5 取消单条明细

```http
POST /company/embed/medical/batch-items/{itemId}/cancel
```

使用条件更新保证已经开始处理的记录不能被并发取消。

## 7. 历史与结果

### 7.1 统一历史列表

```http
GET /company/embed/medical/history
```

筛选参数：`serviceMode`、`entryType`、`processStatus`、`resultStatus`、`beginTime`、`endTime`、分页参数。`entryType` 为 `SINGLE` 或 `BATCH`。

### 7.2 单条请求详情

```http
GET /company/embed/medical/requests/{requestNo}
```

只返回当前 AppKey 对应公司的请求。未上传的精准延时结果不返回草稿数据。

### 7.3 未读结果提醒

```http
GET /company/embed/medical/notifications/unread
```

返回当前公司已完成、已上传且未查看的精准延时结果。

### 7.4 标记结果已查看

```http
POST /company/embed/medical/requests/{requestNo}/read
```

该操作只更新查看状态，不修改查询结果和计费信息。

## 8. Excel 导出

### 8.1 导出单人结果

```http
GET /company/embed/medical/requests/{requestNo}/export
```

返回 `.xlsx`。`PENDING`、`PROCESSING` 不可导出；精准延时 `COMPLETED` 但尚未 `UPLOADED` 时不可导出；`FAILED`、`CANCELLED` 等无结果终态可以导出其状态和说明。不可导出时返回 `409 RESULT_NOT_READY`。

### 8.2 导出整批结果

```http
GET /company/embed/medical/batches/{batchNo}/export
```

批次存在待处理或处理中明细时返回 `409 BATCH_NOT_FINISHED`。终态导出包含全部人员的状态、费用、说明和动态结果字段。

## 9. 管理后台精准延时接口

以下接口继续使用若依管理员 Token 和权限体系，不使用 AppKey：

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| `GET` | `/business/delayed-query/list` | 查询精准延时请求 |
| `GET` | `/business/delayed-query/{id}` | 查看请求及结果详情 |
| `POST` | `/business/delayed-query/{id}/start` | 原子标记开始处理 |
| `POST` | `/business/delayed-query/{id}/result/import-preview` | 解析动态结果 Excel |
| `PUT` | `/business/delayed-query/{id}/result/draft` | 保存动态结果草稿 |
| `POST` | `/business/delayed-query/{id}/complete` | 上传完毕并执行计费判断 |
| `PUT` | `/business/delayed-query/{id}/result` | 修改已上传结果 |

## 10. 状态枚举

| 类型 | 值 |
| --- | --- |
| 服务模式 | `REALTIME`、`DELAYED` |
| 入口类型 | `SINGLE`、`BATCH` |
| 处理状态 | `PENDING`、`PROCESSING`、`COMPLETED`、`FAILED`、`CANCELLED` |
| 上传状态 | `NOT_UPLOADED`、`UPLOADED` |
| 结果状态 | `HIT`、`NO_RESULT`、`HINT_ONLY`、`FAILED`、`CANCELLED` |
| 查看状态 | `UNREAD`、`READ` |
| 批次状态 | `PENDING`、`PROCESSING`、`COMPLETED`、`PARTIAL_FAILED`、`PARTIAL_CANCELLED`、`CANCELLED` |

## 11. 错误码

| HTTP | `errorCode` | 含义 |
| ---: | --- | --- |
| 400 | `INVALID_PARAM` | 参数缺失或格式错误 |
| 400 | `INVALID_FILE_TYPE` | 不是 `.xlsx` 或 `.xls` |
| 400 | `BATCH_LIMIT_EXCEEDED` | 名单超过 500 人 |
| 400 | `VALIDATION_FAILED` | 预览数据仍有错误 |
| 401 | `INVALID_APP_KEY` | AppKey 缺失或无效 |
| 403 | `COMPANY_DISABLED` | 保险公司已停用 |
| 403 | `DATA_FORBIDDEN` | 访问其他公司数据 |
| 404 | `REQUEST_NOT_FOUND` | 请求不存在 |
| 404 | `BATCH_NOT_FOUND` | 批次不存在 |
| 409 | `INVALID_STATE` | 当前状态不允许该操作 |
| 409 | `NOT_CANCELLABLE` | 记录已经开始处理或已结束 |
| 409 | `RESULT_NOT_READY` | 精准结果尚未上传 |
| 409 | `BATCH_NOT_FINISHED` | 批次尚未进入终态 |
| 402 | `SERVICE_LIMIT_REACHED` | 月度服务额度不足 |
| 503 | `SOURCE_UNAVAILABLE` | 实时数据源不可用 |
| 500 | `INTERNAL_ERROR` | 平台内部异常 |

## 12. 兼容要求

- 保持现有 `AjaxResult` 的 `code/msg/data` 外层结构；
- 新错误增加稳定的 `errorCode`，页面不得依赖中文 `msg` 判断逻辑；
- 现有 `/company/embed/medical/query-types`、`query`、`usage` 路径不变；
- 新页面不调用 `/open/api/medical/query`；
- 所有详情、取消和导出接口必须在服务端校验 `company_id`，不能只依赖前端隐藏。
