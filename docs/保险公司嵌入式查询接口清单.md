# 保险公司嵌入式查询接口清单

> 日期：2026-08-14  
> 状态：接口契约草案，统一鉴权、基础信息、单人实时和单人精准延时接口已实现
> 保险公司接口前缀：`/company/embed/medical`

## 1. 通用约定

所有接口通过请求头传递 AppKey：

```http
X-App-Key: <company-app-key>
```

`/company/embed/medical/**` 由统一拦截器鉴权。AppKey 缺失或无效返回 HTTP 401 和 `INVALID_APP_KEY`；公司停用返回 HTTP 403 和 `COMPANY_DISABLED`。CORS 预检请求不要求 AppKey，正式业务请求必须携带该请求头。

JSON 成功响应：

```json
{
  "code": 200,
  "msg": "success",
  "data": {}
}
```

JSON 失败响应：

```json
{
  "code": 400,
  "msg": "姓名和身份证号不能为空",
  "errorCode": "INVALID_PARAM"
}
```

列表接口统一支持 `pageNum`、`pageSize`。时间使用 `yyyy-MM-dd HH:mm:ss`，金额使用十进制定点数，批次编号和请求编号以字符串返回。

## 2. 已有接口处理策略

| 现有接口 | 处理策略 |
| --- | --- |
| `GET /query-types` | 保留，返回当前公司可用的实时查询项目和价格 |
| `POST /query` | 保留并规范为单人实时查询，不承担精准延时提交 |
| `GET /usage` | 保留，返回月度额度和服务状态 |
| `/open/api/medical/query` | 不供新嵌入页面使用，后续单独评估兼容性 |

## 3. 接入与基础信息

### 3.1 验证 AppKey

```http
GET /company/embed/medical/access
```

返回当前公司脱敏信息、服务状态和能力开关。页面以此接口结果作为“已接入”的唯一依据。

```json
{
  "companyName": "测试保险公司",
  "companyCode": "TEST",
  "appKeyMasked": "1234****cdef",
  "billingMonth": "2026-08",
  "budgetEnabled": true,
  "serviceStatus": "NORMAL",
  "capabilities": {
    "singleRealtime": true,
    "batchRealtime": true,
    "singleDelayed": false,
    "batchDelayed": false,
    "singleExport": true,
    "batchExport": true
  }
}
```

接口不返回保险公司数据库 ID、完整 AppKey、密码或联系人信息。精准延时价格类型及公司权限启用后，延时能力开关才为 `true`。

### 3.2 查询项目

```http
GET /company/embed/medical/query-types
```

仅返回启用且当前公司有权使用的实时查询项目：

```json
{
  "queryType": "medical_all",
  "queryName": "医疗大数据",
  "hitFee": 50.00,
  "noResultFee": 0.00
}
```

公司级价格存在时使用公司配置；公司级配置停用时不返回该项目；没有公司级配置时回退全局启用价格。`precision_delayed` 不出现在实时项目列表中。按照计费规则，`noResultFee` 始终返回 `0.00`。

### 3.3 月度用量

```http
GET /company/embed/medical/usage
```

沿用现有预算、已使用、已预留、剩余额度和服务状态字段。

```json
{
  "budget": 10000.00,
  "usedAmount": 3000.00,
  "reservedAmount": 500.00,
  "remaining": 6500.00,
  "usagePercent": 35,
  "billingMonth": "2026-08",
  "budgetEnabled": true,
  "serviceStatus": "NORMAL"
}
```

额度达到 80% 返回 `NEAR_LIMIT`，达到或超过上限返回 `LIMIT_REACHED`。预算控制关闭时返回 `budgetEnabled=false` 和 `serviceStatus=NORMAL`，不会因预算金额为零误报额度耗尽。

## 4. 单人查询

### 4.1 单人实时查询

```http
POST /company/embed/medical/query
Content-Type: application/json
```

```json
{
  "queryType": "medical_all",
  "queryParams": {
    "name": "张三",
    "idCard": "430102199001011234"
  }
}
```

返回 `requestNo`、`processStatus`、`uploadStatus`、`resultStatus`、实际费用和脱敏后的动态 `data`：

```json
{
  "code": 200,
  "msg": "操作成功",
  "data": {
    "code": "0",
    "msg": "success",
    "queryId": 1024,
    "requestNo": "MR20260817113000123A1B2C3D4",
    "processStatus": "COMPLETED",
    "uploadStatus": "UPLOADED",
    "resultStatus": "HIT",
    "serviceStatus": "NORMAL",
    "fee": 50.00,
    "data": {}
  }
}
```

`HIT` 按当前公司的查得价格计费；`NO_RESULT` 和查询失败固定为 `0.00`。查询失败会返回 `SOURCE_UNAVAILABLE`，同时保留失败日志并释放已预留额度。

### 4.2 单人精准延时提交

```http
POST /company/embed/medical/delayed/requests
Content-Type: application/json
```

```json
{
  "name": "张三",
  "idCard": "430102199001011234"
}
```

返回请求编号、状态和 `reused`。重复未完成请求返回 `200` 及原请求，不以错误处理。

```json
{
  "code": 200,
  "msg": "操作成功",
  "data": {
    "requestNo": "MD20260817114000123A1B2C3D4",
    "processStatus": "PENDING",
    "uploadStatus": "NOT_UPLOADED",
    "resultStatus": null,
    "reused": false,
    "submittedTime": "2026-08-17 11:40:00"
  }
}
```

服务端校验姓名和 18 位身份证号。提交事务会锁定当前公司后检查未完成重复请求，保证同一公司并发提交时只创建并预留一次；已完成、失败或取消的请求允许重新提交。

## 5. 批量导入与提交

### 5.1 下载名单模板

```http
GET /company/embed/medical/batches/template
```

返回 `.xlsx` 文件，列为姓名和身份证号。

### 5.2 解析名单预览

```http
POST /company/embed/medical/batches/import-preview
Content-Type: multipart/form-data
```

表单字段：`file`。只接受 `.xlsx`、`.xls`，文件不超过 10 MB，最多 500 行有效人员数据。完全空白的数据行会忽略；`duplicateCount` 统计重复组内所有被标记为重复的行。

返回：

```json
{
  "totalCount": 3,
  "validCount": 2,
  "invalidCount": 1,
  "duplicateCount": 0,
  "rows": [
    {
      "rowNo": 2,
      "originalName": "张三",
      "originalIdCard": "430102199001011234",
      "name": "张三",
      "idCard": "430102199001011234",
      "valid": true,
      "errors": []
    }
  ]
}
```

### 5.3 重新校验预览数据

```http
POST /company/embed/medical/batches/validate
Content-Type: application/json
```

请求体包含页面修改后的 `rows`，返回与导入预览相同的统计和校验结果，不创建正式记录。

### 5.4 创建批次

```http
POST /company/embed/medical/batches
Content-Type: application/json
```

```json
{
  "serviceMode": "REALTIME",
  "queryType": "medical_all",
  "rows": [
    { "rowNo": 2, "name": "张三", "idCard": "430102199001011234" }
  ]
}
```

`serviceMode` 最终支持 `REALTIME` 或 `DELAYED`。当前非实时优先阶段只开放 `DELAYED`，并忽略 `queryType`；`REALTIME` 批次将在延后阶段开放。服务端重新执行全部校验后，以单一事务创建批次、请求和成员明细。

精准延时批次提交返回批次状态和逐行请求关联：

```json
{
  "batchNo": "B202608171400000001234567890",
  "batchStatus": "PENDING",
  "totalCount": 2,
  "pendingCount": 1,
  "processingCount": 1,
  "reusedCount": 1,
  "totalFee": 0.00,
  "items": [
    {
      "rowNo": 2,
      "requestNo": "MD2026081713590000012345678",
      "reused": true,
      "processStatus": "PROCESSING",
      "uploadStatus": "NOT_UPLOADED"
    }
  ]
}
```

同公司、同姓名和身份证号存在未完成精准延时请求时，成员复用原请求且不重复预留额度。新请求才写入 `reservedFee`；`totalFee` 是实际已确认费用，提交时固定为 `0.00`。

## 6. 批次与明细

### 6.1 批次历史

```http
GET /company/embed/medical/batches
```

筛选参数：`serviceMode`、`batchStatus`、`beginTime`、`endTime`、分页参数。

### 6.2 批次详情

```http
GET /company/embed/medical/batches/{batchNo}
```

返回批次统计、费用汇总和是否允许整批取消/导出。

进度由批次成员和请求当前状态实时汇总，包括 `pendingCount`、`processingCount`、`completedCount`、`failedCount`、`cancelledCount`、`cancellableCount` 和实际费用。结果上传后无需等待额外任务即可看到最新状态。

### 6.3 批次人员明细

```http
GET /company/embed/medical/batches/{batchNo}/items
```

筛选参数：`processStatus`、`resultStatus`、`keyword`、分页参数。

### 6.4 取消整个批次

```http
POST /company/embed/medical/batches/{batchNo}/cancel
```

仅将符合 `PENDING + NOT_UPLOADED` 的明细改为 `CANCELLED`。返回取消数量、不可取消数量和最新批次状态。

整批取消会跳过已经开始处理的人员，并通过 `notCancellableCount` 返回跳过数量；如果整批没有任何可取消人员且仍存在处理中人员，则返回 `409 NOT_CANCELLABLE`。

### 6.5 取消单条明细

```http
POST /company/embed/medical/batch-items/{itemId}/cancel
```

使用条件更新保证已经开始处理的记录不能被并发取消。

复用成员只取消当前批次关联，不修改原请求。非复用成员仅在请求没有其他活动批次引用时取消底层请求并释放预留额度；取消不生成费用，也不保存取消人、取消时间或取消原因。

## 7. 历史与结果

```http
GET /company/embed/medical/history/requests
GET /company/embed/medical/history/batches
GET /company/embed/medical/notifications/unread
POST /company/embed/medical/requests/{requestNo}/read
```

单人历史支持 `requestNo`、`name`、`processStatus`、`resultStatus`、`beginTime` 和 `endTime` 筛选，最多返回最近 100 条。历史列表不包含动态结果数据；只有 `GET /company/embed/medical/requests/{requestNo}` 会在结果已上传时返回单人结果。

批次历史最多返回最近 100 个精准延时批次，进度根据成员当前状态实时汇总。未读数量只统计已完成、已上传且尚未查看的请求；标记已查看按当前 AppKey 公司隔离且可重复调用。

### 7.1 统一历史列表

```http
GET /company/embed/medical/history
```

筛选参数：`serviceMode`、`entryType`、`processStatus`、`resultStatus`、`beginTime`、`endTime`、分页参数。`entryType` 为 `SINGLE` 或 `BATCH`。

### 7.2 单条请求详情

```http
GET /company/embed/medical/requests/{requestNo}
```

只返回当前 AppKey 对应公司的请求。未上传的精准延时结果不返回草稿数据。

详情中的姓名、身份证号和动态结果按脱敏规则返回。`resultVisible=false` 表示当前只能查看状态；只有 `uploadStatus=UPLOADED` 且结果记录存在时，才返回 `columnSchema`、`data` 和 `resultSummary`。其他公司的请求编号按不存在处理并返回 `404 REQUEST_NOT_FOUND`。

### 7.3 未读结果提醒

```http
GET /company/embed/medical/notifications/unread
```

返回当前公司已完成、已上传且未查看的精准延时结果。

### 7.4 标记结果已查看

```http
POST /company/embed/medical/requests/{requestNo}/read
```

该操作只更新查看状态，不修改查询结果和计费信息。

## 8. Excel 导出

### 8.1 导出单人结果

```http
GET /company/embed/medical/requests/{requestNo}/export
```

返回 `.xlsx`。`PENDING`、`PROCESSING` 不可导出；精准延时 `COMPLETED` 但尚未 `UPLOADED` 时不可导出；`FAILED`、`CANCELLED` 等无结果终态可以导出其状态和说明。已上传结果导出动态字段。不可导出时返回 `409 RESULT_NOT_READY`。

### 8.2 导出整批结果

```http
GET /company/embed/medical/batches/{batchNo}/export
```

批次存在待处理或处理中明细时返回 `409 BATCH_NOT_FINISHED`。终态导出包含全部人员的状态、费用、说明和动态结果字段。

## 9. 管理后台精准延时接口

以下接口继续使用若依管理员 Token 和权限体系，不使用 AppKey：

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| `GET` | `/business/delayed-query/list` | 查询精准延时请求 |
| `GET` | `/business/delayed-query/batches/list` | 查询精准延时批次及实时汇总进度 |
| `GET` | `/business/delayed-query/batches/{id}` | 查看批次概要和人员明细 |
| `GET` | `/business/delayed-query/{id}` | 查看请求及结果详情 |
| `POST` | `/business/delayed-query/{id}/start` | 原子标记开始处理 |
| `POST` | `/business/delayed-query/{id}/result/import-preview` | 解析动态结果 Excel |
| `PUT` | `/business/delayed-query/{id}/result/draft` | 保存动态结果草稿 |
| `POST` | `/business/delayed-query/{id}/complete` | 上传完毕并执行计费判断 |
| `PUT` | `/business/delayed-query/{id}/result` | 修改已上传结果 |

列表支持请求编号、公司名称、姓名、身份证号、处理状态、上传状态、结果状态和提交时间筛选。开始处理只允许原子执行 `PENDING -> PROCESSING`。

结果导入只接受不超过 10 MB 的 `.xlsx/.xls`，最多 100 个动态字段和 5000 行结果；接口只返回可编辑预览，不直接写数据库。草稿仅允许在 `PROCESSING + NOT_UPLOADED` 状态保存，保险公司端不可见。

上传完毕请求包含 `resultStatus`、`columnSchema`、`data` 和 `resultSummary`。`HIT` 必须有实际结果数据并执行计费；`NO_RESULT`、`HINT_ONLY` 不收费，`HINT_ONLY` 必须填写说明。上传完毕后，结果、额度确认、查询日志和请求终态在同一事务内提交。

修改已上传结果时必须提供 `updateReason`，只能修正动态内容和说明并递增结果版本，不能改变已固化的 `resultStatus`、费用和不可修改查询日志。

## 10. 状态枚举

| 类型 | 值 |
| --- | --- |
| 服务模式 | `REALTIME`、`DELAYED` |
| 入口类型 | `SINGLE`、`BATCH` |
| 处理状态 | `PENDING`、`PROCESSING`、`COMPLETED`、`FAILED`、`CANCELLED` |
| 上传状态 | `NOT_UPLOADED`、`UPLOADED` |
| 结果状态 | `HIT`、`NO_RESULT`、`HINT_ONLY`、`FAILED`、`CANCELLED` |
| 查看状态 | `UNREAD`、`READ` |
| 批次状态 | `PENDING`、`PROCESSING`、`COMPLETED`、`FAILED`、`PARTIAL_FAILED`、`PARTIAL_CANCELLED`、`CANCELLED` |

## 11. 错误码

| HTTP | `errorCode` | 含义 |
| ---: | --- | --- |
| 400 | `INVALID_PARAM` | 参数缺失或格式错误 |
| 400 | `INVALID_FILE_TYPE` | 不是 `.xlsx` 或 `.xls` |
| 400 | `BATCH_LIMIT_EXCEEDED` | 名单超过 500 人 |
| 400 | `VALIDATION_FAILED` | 预览数据仍有错误 |
| 401 | `INVALID_APP_KEY` | AppKey 缺失或无效 |
| 403 | `COMPANY_DISABLED` | 保险公司已停用 |
| 403 | `DATA_FORBIDDEN` | 访问其他公司数据 |
| 404 | `REQUEST_NOT_FOUND` | 请求不存在 |
| 404 | `BATCH_NOT_FOUND` | 批次不存在 |
| 409 | `INVALID_STATE` | 当前状态不允许该操作 |
| 409 | `NOT_CANCELLABLE` | 记录已经开始处理或已结束 |
| 409 | `RESULT_NOT_READY` | 精准结果尚未上传 |
| 409 | `BATCH_NOT_FINISHED` | 批次尚未进入终态 |
| 402 | `SERVICE_LIMIT_REACHED` | 月度服务额度不足 |
| 503 | `SOURCE_UNAVAILABLE` | 实时数据源不可用 |
| 500 | `INTERNAL_ERROR` | 平台内部异常 |

## 12. 兼容要求

- 保持现有 `AjaxResult` 的 `code/msg/data` 外层结构；
- 新错误增加稳定的 `errorCode`，页面不得依赖中文 `msg` 判断逻辑；
- 现有 `/company/embed/medical/query-types`、`query`、`usage` 路径不变；
- 新页面不调用 `/open/api/medical/query`；
- 所有详情、取消和导出接口必须在服务端校验 `company_id`，不能只依赖前端隐藏。
