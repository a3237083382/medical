# 实时查询三表输出实施计划

## 目标

将保险公司单人实时查询改为“身份证号 + 开始时间 + 结束时间”，由后端调用数产可信空间 SDK，并把每次就诊结果按基本信息、电子病历、医学影像检查三类表返回页面。

## 实施范围

### 1. 页面输入与请求

- 修改 `index.html` 实时查询表单，删除姓名输入，增加开始时间和结束时间输入。
- 校验身份证号格式、开始时间和结束时间的必填性及时间先后关系。
- 请求体统一为：

```json
{
  "sfzhm": "身份证号",
  "startdate": "yyyy-MM-dd HH:mm:ss",
  "enddate": "yyyy-MM-dd HH:mm:ss"
}
```

- 批量导入实时查询名单使用 Excel，列为身份证号、开始时间、结束时间；不再要求姓名列。

### 2. 后端接口契约

- 单人实时接口接收 `sfzhm`、`startdate`、`enddate`，拒绝缺失或多余的旧身份参数。
- 保留现有公司 AppKey 鉴权、额度预留、查询日志和结果状态机制。
- 外部 SDK 调用放在数据源适配层，SDK 凭据从配置读取，不写入前端或业务代码。
- 统一处理 SDK 成功、无结果、超时和网络异常，向页面返回稳定错误信息。

### 3. 数据源适配

- 在 `DigitalIndustryDataSource` 中复用 `MisuanDemoTesthua.java` 的 SDK 初始化和调用方式。
- 将页面参数映射为 `sfzhm`、`startdate`、`enddate` 后发送给数产可信空间。
- 解析返回体的 `res` 数组，保留每个元素的原始字段和值。
- 外部 SDK 示例文件仅作参考，不修改该文件。

### 4. 三表结果组织

- 每个 `res` 元素生成一个就诊结果单元，并保留原始顺序。
- 基本信息表始终生成。
- `jzlx` 为“住院”时生成电子病历表；存在影像字段时生成医学影像检查表。
- 按真实返回字段修正：`ryrq` 用于判断住院/门诊；住院固定生成电子病历和医学影像检查表，门诊仅生成基本信息表。
- 增加兼容判断：当历史或不同数据源版本将就诊类型放在 `jzlx` 或基本信息字段时，页面仍会按“住院”补齐电子病历和医学影像检查表。
- 实时查询页面改为提交后仅显示状态和历史记录，点击记录“查看”进入独立结果视图，并复用返回按钮返回查询列表；精准延时详情流程保持不变。
- 历史记录及详情顶部姓名优先读取结果基本信息，不再显示“未提供”；基本信息、电子病历、医学影像检查三张表均统一以姓名、身份证号码为前两列。
- 页面渲染层增加固定列排序，兼容历史结果字段顺序，确保三张表始终以姓名、身份证号码为前两列。
- 三张表已按表结构分别固定列顺序：基本信息从序号、姓名、身份证号码开始；电子病历从姓名、身份证号码开始；医学影像检查从姓名、身份证号码、医院名称开始。
- 详情页按就诊次数折叠展示，每次就诊默认仅显示记录标题，点击“展开”后显示该次就诊包含的表，支持再次收起。
- 页面保存当前查询模式、查询对象、数据类型及输入条件，刷新后自动恢复；就诊记录标题显示就诊类型和对应时间范围。
- 住院标题的入院、出院时间之间使用“至”连接。
- 按 `docs/实时查询结果三表映射设计.md` 的 27 个字段映射中文列名。
- 空值统一为空字符串，日期统一为页面约定格式。

### 5. 页面展示

- 页面按就诊记录分组显示表格标题、就诊类型和就诊序号。
- 不同就诊记录之间不合并；门诊结果不显示空的病历和影像表。
- 身份证号码按当前测试要求完整显示，生产环境继续保留脱敏开关能力。

## 验证标准

1. 单人提交只填写身份证号、开始时间、结束时间即可发起请求。
2. 后端日志中的外部请求只包含 `sfzhm`、`startdate`、`enddate`。
3. 一次返回多条就诊记录时，页面逐条显示。
4. 住院记录显示三张表，门诊记录只显示基本信息表。
5. 27 个字段的中文列名与表结构文档一致。
6. 缺少参数、时间范围错误、外部服务异常时页面显示明确错误，且不产生错误计费。
7. 现有后端测试、前端构建和 JavaScript 语法检查全部通过。

## 实施顺序

1. 修改并测试后端请求对象和数据源适配层。
2. 修改后端结果映射与接口响应。
3. 修改 `index.html` 输入、提交和三表渲染。
4. 更新接口清单和示例文档。
5. 执行单元测试、构建和测试网关联调。

### 实时批量 Excel

- 已支持实时模式上传 Excel，按身份证号、开始时间、结束时间解析和校验。
- 批量提交逐行调用实时大数据查询，页面预览显示时间范围并在历史记录中查看结果。

### 就诊记录去重

- 当前阶段仅处理后端就诊记录去重，不调整电子病历字段和版式。
- 住院唯一键为身份证号、医院名称、就诊类型、入院时间、出院时间。
- 门诊唯一键为身份证号、医院名称、就诊类型、就诊时间。
- 时间先统一格式后比较；相同唯一键的记录合并为一次就诊，但组内原始记录全部保留，并在各类表中分别作为多行展示。
- 就诊组按入院时间或就诊时间升序排列，最早的就诊组显示为第 1 次。
- 多行就诊组展示时，历史和详情页姓名、身份证号及就诊标题时间从组内首个非空值读取；表格列继续按固定字段顺序输出。
- 同一就诊组中不同字段值分别保留为多行；完全相同的表格明细行去重。
- 详情页按门诊、住院分区展示，各分区内按就诊时间升序排列。
- 切换实时/延时查询类型或单人/批量对象时自动退出当前详情并刷新对应历史记录，避免结果串台。
- 门诊和住院详情分别使用独立序号，标题格式为“第N次门诊记录”和“第N次住院记录”，各自从 1 开始。
- 基本信息表首列显示为“就诊id”；门诊不显示入院/出院日期，住院不显示就诊时间。
- 切换实时/延时查询类型时保存当前条件并执行整页刷新，刷新后恢复新选择的查询类型，避免旧详情残留。
