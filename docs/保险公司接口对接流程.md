# 保险公司接口对接流程

## 1. 对接准备

1. 运营方在后台创建保险公司账号，系统自动生成 `AppKey` 和 `AppSecret`。
2. 运营方通过线下安全渠道交付 `AppKey`、`AppSecret`、测试地址、正式地址和接口文档。
3. 保险公司先在测试环境完成签名认证、医疗查询、余额查询和错误码处理。
4. 测试通过后，由运营方切换正式地址并完成余额初始化。

## 2. 通用请求头

所有正式开放接口统一使用以下请求头：

| 请求头 | 说明 |
| --- | --- |
| `X-App-Key` | 保险公司 AppKey |
| `X-Timestamp` | 当前毫秒时间戳 |
| `X-Nonce` | 每次请求唯一随机串，6 分钟内不可重复 |
| `X-Sign` | HMAC-SHA256 签名 |

签名明文：

```text
timestamp + "\n" + nonce + "\n" + body
```

签名密钥为 `AppSecret`，输出为小写十六进制字符串。`GET` 请求 body 按空字符串计算。

## 3. 医疗数据查询

请求地址：

```text
POST /api/v1/medical/query
```

请求体：

```json
{
  "queryType": "medical_all",
  "queryParams": {
    "name": "张三",
    "idCard": "430102199001011234"
  }
}
```

处理规则：

- 签名不合法返回 `401`。
- 保险公司停用返回 `4002`。
- 结算后余额小于 `0` 返回 `4001`，不查询。
- 查询类型未启用返回 `4003`。
- 查询成功后写入查询日志和本次查询费用，不实时扣余额，不立即写扣费流水。
- 结算周期到期后，由若依自带定时任务统一汇总未结算查询日志，扣减余额并写入 `SETTLEMENT` 费用流水。
- 返回给保险公司的医疗数据必须经过脱敏处理。

## 4. 余额查询

请求地址：

```text
GET /api/v1/balance/query
```

`GET` 请求签名时 body 使用空字符串。

返回字段：

| 字段 | 说明 |
| --- | --- |
| `companyId` | 保险公司 ID |
| `companyName` | 保险公司名称 |
| `balance` | 当前余额 |
| `balanceUpdateTime` | 余额更新时间 |

## 5. 精准延时查询

精准延时查询用于保险公司提交姓名和身份证号后，由平台运营人员人工查询并上传结果。该服务不要求保险公司停留在页面等待。

### 5.1 提交请求

请求地址：

```text
POST /company/api/delayed-query/submit
```

请求体：

```json
{
  "patientName": "张三",
  "idCard": "430102199001011234"
}
```

处理规则：

- 姓名和身份证号不能为空。
- 同一公司、同一姓名、同一身份证号如果已有未完成请求，系统返回已有请求，不重复创建。
- 新请求默认 `queryStatus=PENDING`、`uploadStatus=NOT_UPLOADED`。
- 提交时按公司级 `delayed_precise` 查询价格的较高标准预留本月服务额度。
- 提交成功不写实际扣费流水；实际费用在“上传完毕”后进入查询日志，之后由周期结算任务统一写入费用流水。

### 5.2 查询列表

请求地址：

```text
GET /company/api/delayed-query/list
```

返回当前公司自己的精准延时请求。保险公司只能看到本公司数据。

### 5.3 批量提交请求

请求地址：

```text
POST /company/api/delayed-query/submit-batch
```

请求体：

```json
{
  "items": [
    {
      "patientName": "张三",
      "idCard": "430102199001011234"
    },
    {
      "patientName": "李四",
      "idCard": "430102199202021234"
    }
  ]
}
```

处理规则：

- 每个 `items` 元素按一条精准延时请求处理，返回值为请求数组。
- `patientName` 也兼容字段名 `name`，便于保险公司复用原实时查询字段。
- 同一批次内或历史未完成请求中存在同一公司、同一姓名、同一身份证号时，返回已有未完成请求，不重复创建。
- 新创建的每条请求都按 `delayed_precise` 较高标准预留本月服务额度；重复返回已有请求不重复预留。

### 5.4 查看详情

请求地址：

```text
GET /company/api/delayed-query/{id}
```

返回规则：

- `uploadStatus=NOT_UPLOADED` 时只返回请求状态，不返回草稿明细。
- `uploadStatus=UPLOADED` 时返回最新结果说明和结果明细。
- `resultStatus=HIT` 表示查得并按查得价格入账。
- `resultStatus=NO_RESULT` 表示未查得，本次不扣费。
- `resultStatus=PARTIAL` 表示有提示无明细，当前按待确认口径记录，不扣费。

## 6. 周期结算配置

所有保险公司使用同一个结算周期。管理员在若依管理端的“系统监控 / 定时任务”中维护一个周期结算任务，调用目标字符串示例：

```text
billingSettlementTask.settleDueCompanies(14)
```

括号里的数字就是全局结算周期天数。改成 `7` 就表示所有保险公司统一按 7 天结算，改成 `14` 就表示所有保险公司统一按 14 天结算。

cron 表达式只控制检查频率，建议每天凌晨检查一次：

```text
0 0 2 * * ?
```

## 7. 联调验收

联调至少覆盖：

- 正确签名请求成功。
- 缺少签名头返回 `401`。
- 错误签名返回 `401`。
- 重复 `Nonce` 返回 `401`。
- 过期时间戳返回 `401`。
- 当前余额大于等于 `0` 时，周期内查询成功且不实时扣余额。
- 查询成功生成查询日志，费用流水由周期结算任务统一生成。
- 周期结算后余额小于 `0` 时拒绝继续查询。
- 精准延时提交成功后立即返回待处理状态。
- 精准延时上传完毕前不返回草稿明细。
- 精准延时上传完毕后可查看结果，并进入月度账单统计。
- 精准延时未查得结果不扣费，已预留额度被释放。

## 8. 真实数据源开通后的补充事项

真实接口开通后，需要补齐数据源地址、凭证、字段映射、错误码映射和真实样例，然后重新执行保险公司联调。
