## 1. 业务背景

保险公司在承保前需要查询投保人的医疗健康数据，用于风险评估。平台提供两种服务：

1. **实时数据查询** — 调用医保局/卫健委接口获取数据，经平台脱敏/分类处理后返回给保险公司（仅展示风险等级+疾病大类，不展示详细诊断）。
2. **历史数据查询** — 查询平台本地数据库中的详细历史医疗数据。

本需求针对**非实时（历史）数据**部分。

---

## 2. 数据来源

历史数据有两个来源：

### 2.1 实时查询缓存（主要来源）

保险公司调用实时查询接口时，平台将医保局/卫健委返回的原始数据（脱敏前）同步缓存到本地历史数据库。

**规则：**
- 按"内容对比"判断是否重复 — 每次实时查询后，将返回的原始数据与该患者最近一次缓存的数据做JSON对比
- 如果内容一致 → 跳过，不重复存储
- 如果内容不一致（医保局/卫健委更新了数据） → 追加新记录
- 每人可以有多次缓存记录（对应数据的不同版本）

### 2.2 数据导入补充（辅助来源）

通过管理后台的Excel上传功能，手动导入历史数据作为补充。

**Excel数据类型：**
- **就诊记录（医保数据）** — 含患者姓名、身份证号、就诊医院、科室、日期、诊断、病种等
- **大数据（卫健委数据）** — 以JSON格式存储的灵活数据结构

## 4. 接口说明

### 4.1 历史数据查询接口

```
POST /company/embed/medical/query
{
  "queryType": "history_medical",
  "queryParams": {
    "name": "柳云杰",
    "idCard": "430102201311150014"
  }
}
```

返回：
- 查得数据 → resultStatus=HIT，含 clinicVisits + bigdataRecords
- 未查到 → resultStatus=NO_RESULT，data为空

### 4.2 实时查询缓存逻辑（内部实现）

实时查询接口（medical_insurance、medical_all等）内部增加缓存步骤：

1. 调用数据源获取原始数据
2. 查询历史库该患者最近一条 bigdata 记录的 dataJson
3. 对比 dataJson 与本次原始数据JSON是否一致
4. 不一致 → 写入 biz_his_clinic_visit + biz_his_bigdata
5. 一致 → 跳过
6. 继续执行脱敏并返回
