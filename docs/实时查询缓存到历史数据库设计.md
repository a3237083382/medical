# 实时查询结果缓存到历史数据库 — 设计文档

## 概述

保险公司调用实时查询接口时，将查询到的原始数据同时缓存到本地历史数据库中。后续通过历史数据查询接口可查看详细数据。

## 业务规则

1. **每人只存一次** — 实时查询某患者时，先检查历史库中是否已有该患者的记录（按姓名+身份证号）。如有则跳过，不重复缓存；如没有则存入。
2. **存的是原始数据** — 缓存的是脱敏前的原始数据（医保局/卫健委接口返回的完整数据），而非脱敏后展示给保险公司的精简数据。
3. **数据源不确定** — 医保局/卫健委接口返回的数据格式可能包含详细诊断信息，也可能已经是分类级别信息。无论格式如何，原样存储。

## 数据流向

```
保险公司调实时接口（medical_insurance / medical_all 等）
  → MedicalQueryServiceImpl.query()
  → medicalDataSource.query(request) → 返回原始数据（脱敏前）
  → 检查历史库中是否已有该患者记录
     → 无 → 存入 biz_his_clinic_visit + biz_his_bigdata
     → 有 → 跳过
  → DesensitizeUtil.desensitize(原始数据) → 脱敏后返回给保险公司
```

## 存储方式

原始数据以两种形式存储：

1. **biz_his_clinic_visit（结构化）** — 提取原始数据中的结构化字段：
   - patientName → patient_name
   - idCard → id_card
   - diagnosis（诊断摘要）→ disease_name
   - source → 数据来源标记（如"medical_insurance"）
   - 其他可解析的结构化字段

2. **biz_his_bigdata（JSON快照）** — 原始数据的完整JSON，保留所有字段：
   - dataJson = 原始数据完整JSON
   - dataCategory = 查询类型（如"医疗保险"、"电子病历"等）

## 影响范围

- **MedicalQueryServiceImpl.java** — 在实时查询分支中，获取原始数据后、脱敏前，加入缓存逻辑
- **IBizHistoryQueryService.java** — 新增 cacheQueryResult() 方法
- **BizHistoryQueryServiceImpl.java** — 实现缓存逻辑（查重 + 插入）

## 不做的事

- 不处理数据更新（每人只存一次，不更新）
- 不处理数据去重（由"每人只存一次"规则保证）
- 不修改脱敏逻辑
- 不修改历史查询逻辑
