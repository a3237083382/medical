# 周期结算扣费设计

## 业务规则

保险公司在一个结算周期内可以持续查询。查询时只写入查询日志和本次查询费用，不实时扣减账户余额，也不立即写扣费流水。

结算周期到期后，由若依框架自带的“系统监控 / 定时任务”统一执行结算：

1. 汇总所有保险公司未结算的成功查询日志费用。
2. 为每家到期且有费用的保险公司写入一条 `SETTLEMENT` 费用流水。
3. 从保险公司余额中扣减本周期汇总费用，允许扣成负数作为欠费状态。
4. 将已结算查询日志写入本次费用流水 ID，避免重复结算。
5. 更新余额更新时间，作为下一轮周期起算时间。

结算后余额小于 `0` 的保险公司停止开放接口查询；余额大于等于 `0` 的保险公司仍可继续查询。

## 若依定时任务配置

结算周期不在保险公司档案里单独维护，而是在若依定时任务的“调用目标字符串”里统一配置。所有保险公司都按这个周期判断是否到期。

示例：统一按 14 天结算。

```text
billingSettlementTask.settleDueCompanies(14)
```

如果要改成 7 天，只修改同一个定时任务的调用目标：

```text
billingSettlementTask.settleDueCompanies(7)
```

cron 表达式只控制“检查频率”。建议每天凌晨检查一次：

```text
0 0 2 * * ?
```

配置建议：

- 任务名称：保险公司周期结算
- 调用目标字符串：`billingSettlementTask.settleDueCompanies(14)`
- cron 表达式：`0 0 2 * * ?`
- 并发执行：禁止
- 状态：正常

管理端点击“执行一次”会立即按当前调用目标里的周期参数执行真实结算，请只在确认需要结算时使用。
